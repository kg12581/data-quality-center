# 规则编写手册

一个用例 = `testcase/<uuid>.yaml`（规则）+ 同名 `testcase/<uuid>.py`（入口）。
本手册只讲 YAML 怎么写；新增用例用 `python scripts/new_case.py --name 订单数据质量` 生成骨架。

## 1. 文件骨架

```yaml
name: 订单数据质量            # 人类可读名字（报告里显示）
description: 订单主表完整性、唯一性与金额一致性
version: 1

vars:                        # 变量：SQL/filter/expected 里用 ${name} 引用
  partition: "1=1"           # 内置变量：source / table / partition（partition 默认 1=1）
  bizdate: "2026-09-16"

sources:                     # 数据源：连接信息在 .env 里，这里只写连接名
  orders:
    type: hive
    conn: hive_mfg
    table: ods_order_di

checks:                      # 规则列表
  - ...
```

## 2. 三种规则形态

### ① SQL 断言（指标模式）

SQL 返回**一行**，和 `expected` 按 `operator` 比较。

```yaml
  - name: 订单金额不得为负
    source: orders
    dim: validity
    severity: high
    description: amount < 0 视为脏数据
    sql: |
      SELECT COUNT(*) FROM ${table}
      WHERE ${partition} AND amount < 0
    expected: 0
    operator: eq
```

- `expected` 是标量 → 比较 SQL 第一列
- `expected` 是映射 → 逐列比较：`expected: {cnt: 0, max_amount: {value: 100000, operator: lte}}`
- `expected` 里也能用变量：`expected: "${min_rows}"`（渲染后会自动还原成数字）
- 多行结果会报错（指标模式要求聚合查询），要明细请用形态 ②

### ② SQL 明细（返回行即失败）

```yaml
  - name: 订单号重复明细
    source: orders
    dim: uniqueness
    severity: high
    sql: |
      SELECT order_no, COUNT(*) AS dup_cnt FROM ${table}
      WHERE ${partition} AND order_no IS NOT NULL
      GROUP BY order_no HAVING COUNT(*) > 1
    mode: rows
    threshold: 0.001      # 失败率 ≤ 0.1% 仍算通过
    sample_limit: 20      # 失败样本最多留 20 行（默认 10，上限 1000）
```

行数记入 `actual`，前 N 行作为失败样本写进报告。

### ③ 快捷方式（自动生成 SQL）

| type | 必填 | 生成的 SQL |
| --- | --- | --- |
| `not_null` | `column` / `columns` | `WHERE col IS NULL`（可加 `treat_empty_as_null`） |
| `unique` | `column` / `columns` | `GROUP BY ... HAVING COUNT(*) > 1` |
| `enum` | `column`、`allowed` | `WHERE col NOT IN (...)` |
| `range` | `column` + `min`/`max` | `WHERE col < min OR col > max` |
| `row_count` | `min` / `max` | `SELECT COUNT(*)` + `gte`/`lte`/`between` |

```yaml
  - { name: 订单号非空, source: orders, dim: completeness, severity: high,
      type: not_null, column: order_no }
  - { name: 分区行数下限, source: orders, dim: completeness, severity: medium,
      type: row_count, min: 1 }
```

快捷方式在本地文件（csv/parquet）上跑之前会**校验列名**，写错直接报错（不会静默变成"假失败"）。

## 3. 字段速查

| 字段 | 说明 |
| --- | --- |
| `name` / `source` / `severity` | 必填；severity 支持 `error/warn/info`（别名 `high/medium/low`、`critical`） |
| `dim` | 数据质量维度：`completeness` / `uniqueness` / `validity` / `consistency` / `accuracy` / `timeliness`（报告按维度汇总） |
| `description` | 说明，只作文档 |
| `sql` / `sql_file` / `query` | SQL 来源三选一；只写 `sql` 会自动推断 `type: sql` |
| `mode` | `metric`（默认，有 expected 时）/ `rows` |
| `expected`（别名 `expect`） | 期望值，标量或映射 |
| `operator` | `eq/ne/gt/gte/lt/lte/between/in/not_in`，默认 `eq` |
| `threshold` | 允许的失败率 0~1（明细模式） |
| `sample_limit` | 失败样本行数，默认 10 |
| `filter` | 额外 WHERE 条件，支持 `${变量}` |
| `vars` | 规则级变量（覆盖顶层/数据源级） |
| `enabled` | `false` 临时停用这条规则 |
| `run_on` | `auto`（默认）/ `frame`（先读成内存表）/ `source`（直接查库） |

`actual` / `result` / `message` 是**运行结果**，由工具回填到报告；规则里写了会被忽略并提示一行
（`--strict-fields` 则直接报错）；只写 `actual` 没有 `expected` 会报错。

## 4. 变量

优先级（低 → 高）：

```
内置(source/table/partition) < 顶层 vars < 数据源 vars < 检查项 vars < 环境变量 DQ_VAR_<NAME> < --var
```

```bash
python main.py --case 订单数据质量 --var partition="dt = '2026-09-16'" --var bizdate=2026-09-16
DQ_VAR_PARTITION="dt = '2026-09-17'" python main.py --case 订单数据质量
```

变量没定义会在**配置阶段**报错并列出可用变量；`${table}` 默认等于数据源名（数据库数据源取 `table`）。

## 5. 写完怎么验证

```bash
python main.py --case 订单数据质量 --list-rules      # 规则名/维度/级别一览
python main.py --case 订单数据质量 --only 订单号 --failed-rows   # 只跑某几条，带失败样本
python main.py --case 订单数据质量 --include-sql     # 报告里带上渲染后的 SQL
```

配置类错误（字段名写错、变量没定义、连接没配、SQL 文件不存在）都会在跑之前报错，退出码 `2`；
数据质量问题会让退出码变成 `1`。
