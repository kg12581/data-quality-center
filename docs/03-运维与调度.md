# 运维与调度手册

## 1. 本地跑

```bash
pip install -r requirements.txt

python main.py                                  # 跑 main.py 里 RULE_SET 指定的用例
python main.py --list-cases                     # 有哪些用例（uuid + name）
python main.py --case 订单数据质量 --list-rules   # 用例里有哪些规则
python main.py --case 订单数据质量 --failed-rows  # 跑 + 控制台看失败样本
```

PyCharm：直接 Run `testcase/<uuid>.py`（文件顶部有本用例的配置区）。

## 2. 只跑部分规则（调试）

```bash
python main.py --case 订单数据质量 --only 订单号          # 名字子串
python main.py --case 订单数据质量 --only "订单号,金额"    # 多条
python main.py --case 订单数据质量 --only "*明细"         # 通配符
```

## 3. 报告

默认输出控制台 + 三份文件，文件名 = 用例文件名（uuid）：

```
reports/<uuid>.json    # summary + results（含 actual/expected/operator/result/failed_rows）
reports/<uuid>.md      # Markdown，适合贴群 / PR / 归档
reports/<uuid>.html    # 单文件页面，失败样本可展开
```

| 参数 | 作用 |
| --- | --- |
| `--report console,md` | 只出指定格式（`json` / `md` / `html` / `all` / `none`） |
| `-o /data/dq/reports` | 换报告目录 |
| `--archive` | 额外往 `<报告目录>/history/` 留一份带时间戳的历史报告 |
| `--include-sql` | 报告里带上渲染后的 SQL（排查用） |
| `--summary-json` | stdout 再打印一行 JSON 摘要，供调度器/监控解析 |

`--summary-json` 输出示例（单行）：

```json
{"name":"订单数据质量","status":"FAIL","exit_code":1,"total":12,"passed":9,"failed":3,"errors":0,
 "duration_ms":842.1,"time":"2026-09-17T02:00:03+08:00","blocking":["金额不得为负"],"reports":["...json"]}
```

## 4. 服务器定时任务

### 4.1 crontab（每天 02:00 跑，失败发告警）

```bash
# 连接信息放服务器上的 /opt/conf/prod.env（不进仓库）
0 2 * * * cd /opt/dq && \
  /opt/dq/venv/bin/python main.py --case 订单数据质量 \
    --env /opt/conf/prod.env --var partition="dt = '$(date -d yesterday +%F)'" \
    --report json,md --archive --summary-json \
    >> /data/dq/logs/order_$(date +%F).log 2>&1 || \
  curl -s -X POST "$ALERT_WEBHOOK" -d "订单数据质量校验失败，见 /data/dq/reports"
```

要点：

- `--env` 指向服务器上的连接配置；也可以完全不落盘地用环境变量注入
- `--var partition=...` 传当天的分区条件（示例用 `date -d yesterday` 取 T-1）
- `--archive` 留痕；日志重定向到按天文件
- 退出码：`0` 通过 / `1` 有 error 级失败 / `2` 配置或参数问题 —— 直接用于告警与重试判断

### 4.2 用例自带默认值

不想每次敲参数，就在 `testcase/<uuid>.py` 顶部配置区写死默认值：

```python
ENV_FILE = "/opt/conf/prod.env"
EXTRA_VARS = {"partition": "dt = '2026-09-16'", "bizdate": "2026-09-16"}
REPORT_FORMATS = ("json", "md")
ONLY = []                      # 例如 ["订单号", "金额"]
```

然后在服务器上直接 `python testcase/<uuid>.py` 即可。

## 5. CI（GitHub Actions）

- `.github/workflows/ci.yml`：push/PR 时在 Python 3.10/3.11/3.12 上跑 pytest + 跑一遍 CSV 示例用例
- `.github/workflows/nightly.yml`：每天定时（或手动触发）跑示例用例，报告作为 artifact 上传

真实业务用例建议放在内网集群侧定时执行（连接信息用服务器环境变量或 `/opt/conf/*.env`），
GitHub 侧只做代码质量门禁。

## 6. 常见运维问题

| 现象 | 处理 |
| --- | --- |
| 退出码 2 | 配置/参数问题：看 stderr 的 `[配置错误]` / `[参数错误]`，通常是变量没定义、连接没配、字段名写错 |
| 所有规则都是 ERROR | 数据源连不上：先单独跑 `--only <一条规则>` 看具体报错（会带 driver/url/jar 信息） |
| 报告太大 | 加 `--report json` 或 `--sampling`? 目前用 `sample_limit` 控制失败样本行数，或去掉 `--include-sql` |
| 想对比历史 | 用 `--archive`，历史报告在 `reports/history/<uuid>_<时间戳>.json` |
| 只想看某几条规则结果 | `--only`（支持子串/通配符/逗号分隔） |
